Architecture & Protocol Specification

How ChunkStream splits, verifies, tracks, and resumes transfers across devices.

Transfer Protocol Pipeline

  1. 1. Slicing & Hash Header: File is partitioned into fixed-size chunks (e.g. 256 KB). SHA-256 is computed for each chunk and for the entire payload.
  2. 2. SQLite Ledger: Session is registered in transfers table. Incoming chunks are saved as discrete .part files and indexed in chunks.
  3. 3. Real-Time WebSocket Relay: Chunks are streamed through /ws/transfer/{id}. Sender receives immediate ACKs; Receiver receives chunk payloads.
  4. 4. Reassembly & Integrity Verification: Upon receiving all chunks, the server concatenates .part files into the final file and verifies the combined SHA-256 digest.
  5. 5. Interruption & Resumption: If a connection drops, Receiver emits {"type": "resume_request"}. Server calculates set difference (total_chunks - acknowledged_chunks) and instructs Sender to re-stream only the missing set.

ProdPilot REST API Reference

GET /api/health Uptime probe (200 OK / 503 Outage)
GET /api/logs?limit=100&min_level=ERROR ProdPilot log batch ingestion
POST /api/test/fail Injects failure scenario (F1, F3, F4, F6)
POST /api/test/crash Simulates fatal unhandled crash (F2)
GET /api/transfers/{id} Retrieves acknowledged & missing chunk lists
WS /ws/transfer/{id}?role=sender|receiver Bidirectional streaming & relay socket
